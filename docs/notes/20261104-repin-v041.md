# Upstream re-pin `v0.4.0 → v0.4.1` (2026-11-04)

**Pin `v0.4.0` → `v0.4.1` (`8a5d6e2c`, 2026-10-08)**: 439 commits and 63 merged PRs.
Issue #455, PR #456. This is step two of the tag-by-tag walk to `v0.4.7`
([v0.4.0 note](20261104-repin-v040.md)).

## 1. What moved

Nothing that is vendored moved: `core_overlay/`, `vendored_gem_sigs/`, the plugin sig,
`capability_roles/`, effects, `UNBUILDABLE_DEFINITIONS` and the conformance load set are all
exact. rbs stays 4.2.0. Upstream's `data/` moved only in `oss-sweep/`. Most of the release is
`--incremental` and cache work, which the port does not mirror.

## 2. Raw bump: 0 fixture FPs, 35 sweep FPs, one family

All 35 sweep FPs are `def.override-visibility-reduced`, and every one was a row v0.4.0 had
matched. MATCHED fell by exactly 35: mastodon 420→410, gitlab 1088→1079, mail 9649→9648,
concurrent 5714→5699.

**Upstream change (#1578, #1594, #1606, #1623, #1631, ADR-119):** lookups follow Ruby's
ancestor order, and upstream declines wherever that order is not provable. The cases are:
- a mixin edge that is conditional, block-scoped, made in a hook, in receiver form, through
  `send(:include)`, or computed;
- a def that may be absent;
- a visibility that may not hold (`module_function` under a condition, in a block or in a
  `begin`).

Where the order is not provable, upstream does two things:
- **Override lints decline.**
- **The class's own `def` types as `Dynamic`** unless an RBS signature exists for it.

The delta-debugged repro for the whole family was rake's `Rake::Task.prepend Module.new {…}`
in `application.rb`, three files in all.

**Port:**
- **Census:** a per-file ancestry census, `rigor-parse/src/ast/ancestry_facts.rs`. It records
  unordered edges (a wildcard `*` when the edge cannot be named), possibly-absent defs,
  uncertain visibilities and direct prepends.
- **Resolution chain:** `source_index/resolution_chain.rs` builds prepends, then the class,
  then includes (latest first), then the superclass chain, capped at 100 entries.
- **Override lints:** `settled_definer` / `override_parent` replace
  `nearest_ancestor_defining`.
- **Typing gate:** `own_def_typing_settled` gates tier-4b own-def typing and the
  implicit-self literal fold.
- **Fork settling:** one include-side fork is settled when both orders name the same parent.
  Without that, mastodon dropped to 405 and gitlab to 1078 matched.

`call.wrong-arity` needed no change, because the port reads its arity from RBS only.

**Result:** 0 FP. MATCHED counts equal the raw bump on every corpus, so no row was lost to
over-declining.

## 3. Fragment probe

The investigator found three gate-invisible families:
- **A:** `call.undefined-method` on an own def behind an unordered edge (12 rows).
- **B:** a conditional, block or `begin` `module_function` (5 rows).
- **C:** a prepend over a private def, or an uncertain edge on the overriding class (8 rows).

All three are ported in this PR, and the three-way script finds 0 port-only rows across 298
rows. Two pre-existing FPs, an in-body `prepend` and a conditional re-`def`, are filed as #457.
The new layout also happens to fix both. Coverage left behind: `def.method-visibility-mismatch`,
`def.override-return-widened` and `def.override-param-narrowed` are not ported.
Source-arity `call.wrong-arity` is not ported either.

## 4. Lessons

- The sweep-FP count equalled the matched-count drop exactly. When it does, the family is
  "upstream retracted rows we matched", and MATCHED returning to the raw-bump value is the
  test for over-declining.
- One pushed WIP commit skipped `gate.sh` and failed CI. Run the gate before every push.
