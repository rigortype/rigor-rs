## 3. Families (all ported)

The work was split across two implementers working in parallel, and their branches were merged before the
review.

| family | upstream | port change |
|---|---|---|
| core receiver may answer | #2086 | `call.undefined-method` declines on a core receiver when any of these hold. Its RBS ancestor chain has a project `method_missing` or a mixed-in project module that defines the name (receiver-form or `send(:include)`, across files, hooks on the singleton side). The receiver is a local given singleton methods (`extend`, `define_singleton_method`, `class << s`, `instance_eval`, a clone of one). The receiver is class-typed and a project subclass defines the name. A union declines when any arm may answer. The new census is `ast/singleton_locals.rs`, plus `receiver_mixins` and three `SourceIndex` probes. |
| when tests that write | #2036 | A local written inside a `when` test reads `Dynamic[top]` from the write on, within its scope. This replaces v0.4.4's value-position-only widening. |
| definer replaces `def` | #2003 | A later same-file `attr_*`, literal `define_method`, `alias_method` or `alias` blacklists the earlier `def` from tier-4b typing. `attr_writer` covers only `x=`, and a later `def` wins again. |
| attr spellings | #2120 | `self.attr_*` and `send` / `public_send` / `__send__(:attr_*)` file members. A project-sig receiver now also declines on a method the project's source declares. That was a pre-existing FP. |
| module_function copy | #2055 | A def under `module_function`, bare or named, gives its instance copy private visibility on the override parent side. A module function on the override side is skipped. |
| singleton rewrites | #2045, #1936 | `singleton_class.{alias_method, define_method, remove_method, attr_*}`, `define_singleton_method` and `class << self` definers decline a superseded `def self.x` fold. This holds even when the definer is conditional; a non-literal name counts as every name. |
| `severity_overrides` warnings | #2000 | The stderr warnings are ported. This is CLI parity, not an FP. |

**Pre-existing FPs fixed along the way:** `Integer.prepend(Ext)`, `def s.foo; s.foo`, and
`alias_method :x, :y` after `def y`. Eleven unconditional singleton rewrites (#1936) were
also still firing.

**Review fix:** the #2036 retraction also covers `flow.always-truthy-condition`. Its fold snapshot
kept the binding from before the `case`, which produced port-only rows and also flipped truthy and falsey
messages at matched keys. The harness keys on (rule, line, col), so it cannot see those message flips.
The rule now declines when the predicate reads a local that a `when` test wrote. The other leftovers are
filed as #476.

**Not ported:**
- Ivar flow (#2077, #2029, #2017): the port does no ivar typing.
- The `pre_eval:` reach (#2098, #2107, #2130): the port ignores `pre_eval:`. Tracked in #472.
- The new `call.wrong-arity` rows from #2055 and #2045: coverage only.

**Result:** 0 FP, 9,441 files, 650 gaps. MATCHED equals v0.4.4 on every corpus. The three-way probe found
0 port-only rows across 100 repro targets, and 104 controls still fire.

## 4. Lessons

- Two implementers in separate worktrees, merged before review, roughly halved the wall-clock time.
  The only conflict was two independent declines on the same `if` in `call_receiver.rs`, and both
  were kept.
- A must-still-fire control can itself be retracted by the next tag, as fixture 134 was. Regenerated
  controls are the first place a retraction shows up.
