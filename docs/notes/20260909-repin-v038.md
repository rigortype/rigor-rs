# Upstream re-pin `v0.3.4 → v0.3.8` (2026-09-09)

**Pin `b10bd5df` (`v0.3.4`) → `ffb456b0` (`v0.3.8`)**, four releases, 924 commits. Branch
`upstream-pin-v0.3.8`. Verdict and final numbers are in § 6; everything before it is what
the bump cost and why.

The previous two bumps taught one lesson each — `v0.3.2`: the DATA moves (overlay,
`sig/shims`); `v0.3.4`: the LOGIC retracts and only the sweep sees it. This one is both at
once, plus a third thing neither predicted: the reference got **slower by a factor of 30 on
one file**, so the sweep that is supposed to be the finding gate took 70 minutes.

## 5. Findings worth more than the bump

- **The spec's F-A gate was wrong for this port, and the fixture harness would not have
  said so.** "Decline when the argument is `Dynamic[top]`" silenced four of the spec's own
  must-still-fire controls, because the port's fold path sees EVERY def-body local as
  `Dynamic[top]`. The implementer replaced it with a measured syntactic allow-list of
  reference-untyped roots. Fifth failure of a "we do strictly less" argument, first inside
  a spec — [[subset-arguments-need-probing]] again.
- **Six project-class guard rows were live FPs.** Re-probing the port's `projsub` /
  `chain_projsub` test rows against `v0.3.8` showed the reference no longer distinguishes a
  project class from an RBS-less gem class in the `:unknown` arm; rigor-rs had been firing
  `for String` on all six.
- **`Class.typo` / `Module.typo` (singleton reads) were live FPs** no fixture exercised.
- **The bump exposed a live effects OVER: `super`.** `v0.3.5` #446 made `super` contribute
  its parent's effects and taint `unresolved-super` when the parent does not resolve; the
  port ignored `super` entirely, so `effects_diff.py` read `OVER=16` (104 with `--scale`).
  Resolving the ancestry would NOT have been enough — 4 of the 15 mastodon rows are supers
  that resolve onto a tainted parent — so the port taints at every `super`.
  [20260909-repin-v038-effects-super.md](20260909-repin-v038-effects-super.md).
- **The port site for F-C was not `check_call`**: every guarded-parameter row types
  through the narrowing snapshot and fires from `check_narrowed_call`. And
  `CoreIndex::is_module` cannot answer for a qualified name (short-key map) — a new
  `is_qualified_module` mirrors `Environment#rbs_module?`.
- **`"abc"[u].typo` is a pre-existing port FP, not a retraction** — silent on the reference
  at `v0.3.0`, `v0.3.4` and `v0.3.8`. Generic RBS dispatch pins the first of two differing
  `String#[]` arms. Not closed here (needs #521's `join_candidate_returns` in the generic
  dispatch); tracked as a follow-up issue.
- **Upstream performance regression** — `rufo-0.18.2/lib/rufo/formatter.rb` (4,221
  lines) does not finish in 25 minutes at `v0.3.8` (23 s for the whole gem at `v0.3.4`),
  bisected to `acd35612` (#547). The `mail` corpus went 130 s → 4,161 s.
  [feedback batch 4](20260909-upstream-feedback-batch4.md).
- **The reference's version guards fold against the ANALYZER's Ruby.** The port mirrors
  that with `HOST_RUBY_VERSION` / `HOST_RUBY_ENGINE` (4.0.5 / ruby, overridable by
  `RIGOR_RUBY_VERSION` / `RIGOR_RUBY_ENGINE`). **The spec's "decline `Psych::VERSION`,
  both arms live" was itself an FP** — the oracle READS that constant and kills an arm, so
  keeping both arms live reports inside the arm it killed (measured on the
  `mail/lib/mail/yaml.rb` shape #627 was opened for). The port answers `Unreadable` and
  drops BOTH arms: under-emission by construction. Third spec claim the probes overturned.
- **Inside a `->` literal, no local write binds on the reference** — `->(y) { y = 1;
  Float(y).typo }` is silent while `lambda { |q| q = 1; Float(q) }` fires `for 1.0`.
  Ported as measured (the write scan skips `Node::Lambda` interiors). One new gap: a
  same-`def` `@x ||= "s"` is invisible to the ivar root rule (`InstanceVariableOrWrite`
  has no owned arena variant), pinned in fixture 105; no corpus site has that shape.
