# Issue #158 — config path resolution parity

PR #335, merged `232d040` (head `595d800`). Three adversarial review rounds.

## What landed

`rigor-cli/src/config.rs` now resolves config like `Rigor::Configuration`:

- `includes:` diamond + cyclic graphs, key-specific merge semantics, `.rigor.dist.yml` discovery, `~`/`..` expansion, exit-64 fatal config surface across all consumers (check/sig-gen/triage/coverage/effects/plugins/diff/doctor/show-bleedingedge; LSP keeps last-good).
- **Psych parser parity** (the hard part, two fix rounds):
  - `psych_render` rebuilds serde_yaml error markers into `<abs>:<l>:<c>: not valid YAML: <detail>` for 1/2/N-marker shapes — r1 fixed a single-marker slice panic (exit 101 → 64).
  - `DupOkVisitor`: recursive last-wins duplicate keys at every level, plus **inline `<<` merge resolution** — every `<<` occurrence applies in document order, all-Mapping sequences merge element-wise, non-mergeable `<<` stays a literal key (no error path). Replaced `Value::apply_merge()` which collapsed dup `<<` and made `mystery: {<<: 5}` fatal.
  - First YAML document only; doc-2 unparseable is ignored like Psych.
  - Non-string top-level keys stringify via Ruby `to_s` (`1`, `["a", "b"]`, `{x:1}`→`{"x" => 1}`) into the unknown-key warning path instead of `from_value` dying.
  - Non-`ruby/` tags drop (`x: !foo 1` loads); `!ruby/*` stays fatal crash-shape.
  - Invalid UTF-8 renders `invalid leading/trailing UTF-8 octet` exit 64 (was exit 1); UTF-16 BOM → `r:bom|utf-8` ArgumentError surface.
  - `coerce_severity_overrides` ported to the load path: non-Hash → `must be a Hash`, non-String value → `a YAML boolean` (+ `did you mean` only for `false`), unknown severity → `must be one of [:error, :warning, :info, :off]`.
- `doctor` propagates `LoadFailure` (exit 64); `show-bleedingedge` gets the upstream error prefix.
