**Status: landed on `worktree-agent-a7a61997f153c5af1`, branched from
`upstream-pin-v0.3.8` at `e99fc03`.** Implements §§ 7–8 of
[the port spec](20260909-repin-v038-port-spec.md). Every row below was measured
2026-09-09 against the PINNED reference at `ffb456b0` (`rigor 0.3.8`), one fresh
temp cwd per invocation, `--no-cache`, both reference libs on `-I`
(`UPSTREAM.md` hazards 1–3), and against the port on this branch. Host Ruby:
`RUBY_VERSION` `"4.0.5"`, `RUBY_ENGINE` `"ruby"`.

## 1. F-F — the dead arm of a decidable version guard reports nothing

`crates/rigor-rules/src/dead_version_guard.rs`, wired at the three points where
the CLI assembles a file's diagnostics (`main.rs` stage 3, `mcp.rs`'s `check` and
`triage` tools, `lsp.rs`), always AFTER every type/flow rule and BEFORE
`suppression_marker_diagnostics` — the reference's own position
(`check_rules.rb:111`).

### The verdict envelope actually implemented

Folded — ONE comparison call (`< <= > >= == !=`), no block, exactly one PLAIN
positional argument (`args_all_plain`, because the lowering drops splat /
keyword / block-pass arguments from `args` and a `RUBY_VERSION < *pair` would
otherwise read as arity 1), a receiver, and both operands readable:

| operand | kind | notes |
|---|---|---|
| a String literal | `:literal_string` | two bare literals decline (a constant comparison, not a guard) |
| BARE `RUBY_VERSION` | `:string` | compared with **String** semantics — LEXICAL |
| BARE `RUBY_ENGINE` | `:engine` | **equality only**; an ordering declines |
| `Gem::Version.new(<one of those>)` | `:gem_version` | on BOTH sides; **folded, not declined** |
| `Psych::VERSION` | `:string` | see § 1.2 — a THIRD verdict, not a decline |

Declined, both arms live: `RUBY_PLATFORM`, `<=>`, `!` / `&&` / `||`
compositions, `case` subjects, a value read through a local, `.to_f` spellings,
a mixed `Gem::Version`/bare-String pair, a non-curated `Foo::VERSION`, and
`::RUBY_VERSION`.

`Gem::Version` **is folded** (not declined). The comparator is a hand-rolled
`Gem::Version.correct?` + `#<=>`: `@version.strip.gsub("-", ".pre.")`, segments
scanned as `/[0-9]+|[a-z]+/i`, `canonical_segments` split at the first String
segment with each half's trailing numeric zeros dropped, then an element-wise
walk zero-padded to the longer list where a String segment sorts BELOW a
numeric. Pinned by a 23-case unit test whose expectations were generated by
running real `Gem::Version` under the host Ruby (`4.0.5` vs `3.4`, `3.10` vs
`3.9`, `1.0` vs `1.0.0`, `3.1.0.pre1` vs `3.1.0`, `1.0-rc1` vs `1.0`, `1.0.0.0`
vs `1`, `1.a.0` vs `1.a`, `""` vs `0`, …). `correct?` is pinned the same way.

### 1.1 The reference Ruby

`HOST_RUBY_VERSION = "4.0.5"` / `HOST_RUBY_ENGINE = "ruby"` in one place, moved
by `RIGOR_RUBY_VERSION` / `RIGOR_RUBY_ENGINE` (empty reads as unset). Documented
in the module and in `crates/rigor-cli/src/ruby_mode.rs`'s env-var table, next to
`RIGOR_RUBY` / `RIGOR_NO_RUBY` — a DIFFERENT axis that never interacts with
them. `RubyRuntime::from_overrides` is the testable half, so the override is
exercised without mutating the process environment (`"3.3.0"` flips f1's twin
from `:falsey` to `:truthy`).

### 1.2 The spec was wrong about `Psych::VERSION`, and the probe says so

§ 7 says to "decline `Psych::VERSION` entirely (both arms live — a safe
under-claim)". **It is not a safe under-claim, it is a false positive**, and the
first probe run caught it:

```
RS  call.undefined-method @ 119:7
  "abc".frobnicate_f26 if Gem::Version.new(Psych::VERSION) < Gem::Version.new("3.1.0")
```

The oracle READS `Psych::VERSION` out of its own runtime, folds the guard and
kills the `then` arm; declining keeps both arms live and reports inside the arm
the oracle killed. That is the exact `mail/lib/mail/yaml.rb` shape upstream #627
was opened for. Baking a `HOST_PSYCH_VERSION` constant is worse than declining:
a stale value picks the WRONG arm and reports inside the dead one.

Implemented instead: a third verdict, `Verdict::Unreadable` — "a guard whose
SHAPE the reference folds and whose value this port cannot read" — for which the
filter drops **both** arms. Whichever arm the reference kills, the port has
already dropped it; the other arm is a coverage gap and never a false positive.
The set stays the reference's ALLOW-LIST (`VERSION_CONSTANTS = ["Psych::VERSION"]`),
so a non-curated `Foo::VERSION` is plain-undecidable on both engines. Kind rules
still run first, so `Gem::Version.new(Psych::VERSION) < "3.1.0"` (mixed) and
`Psych::VERSION < RUBY_ENGINE` (ordering on an engine) still decline outright.

### 1.3 Two port-specific traps

**The lowering collapses `ConstantReadNode` and `ConstantPathNode` into one
`Node::ConstantRead`.** The reference admits `RUBY_VERSION` only as a
`ConstantReadNode` and `Psych::VERSION` only as a `ConstantPathNode`, so the port
re-derives "bare" as `!name.contains("::") && source[span] == name`. Both terms
are load-bearing and each was caught by a measurement:

* without the source-slice term, `::RUBY_VERSION` (which renders as the bare
  `"RUBY_VERSION"`) would fold — the oracle FIRES there (row f25);
* without the `contains("::")` term, `Psych::VERSION` (whose slice *equals* its
  rendered name) reads as bare — the first unit-test run failed exactly there.

**The arm spans.** `Node::If` already keeps `is_unless`, and `else_body` holds AT
MOST one lowered node (the `elsif` chain's `If`, or the `else` clause's
`BeginRescue` carrier), so its span IS the reference's `node.subsequent` /
`node.else_clause` location; the body arm is the span hull of `then_body`, which
is the reference's `StatementsNode#location`. Coverage is a half-open BYTE range
(`Diagnostic::start_offset`), which is what makes a one-line ternary drop only
its dead half. The port walks every `Node::If` in the arena rather than pruning
the descent into a dead arm, as the reference does — equivalent for a span
filter, because a guard nested inside a dead arm can only contribute subranges.

## 2. F-G — a literal-shape constant the file itself mutates stops folding

Two halves:

* **`crates/rigor-parse/src/ast.rs`** — a `ConstMutation` census collected during
  the lowering walk and hung off `LoweredAst::const_mutations()`. It has to live
  there: `C[i] ||= v` / `C[i] += v` are Prism's `Index{Or,And,Operator}Write`
  nodes, which have no owned variant and fall to the recovered-children carrier
  that ERASES which node was the mutated receiver. Giving them a synthetic
  `Node::Call` would put a `[]=` dispatch in front of every call rule (a fresh
  arity / undefined-method surface) for nothing. The census is RAW — receiver
  name, whether it was written as a path, and the method name, or `None` for a
  site that is a mutation unconditionally (`Index*Write`, and Prism's
  `attribute_write?`).
* **`crates/rigor-infer/src/source_index.rs`** — `mutated_constant_names(ast)`
  applies `ARRAY_MUTATORS ∪ HASH_MUTATORS` (which live in `rigor-infer`) and
  expands a BARE receiver to every lexical candidate (`[A, B]` + `C` ⇒ `A::B::C`,
  `A::C`, `C`; a `A::B` PATH receiver contributes only the name as written).
  `collect_literal_constants` then wraps a matched write's harvested value in the
  new `ConstLit::Widened`, and `Typer::intern_const_lit` turns that into
  `Type::Dynamic(inner)` — the port's spelling of
  `Type::Combinator.dynamic(literal)`.

### The census predicate, exactly

A site counts when its receiver is a `ConstantReadNode` or a statically-nameable
`ConstantPathNode` (the STRICT `qualified_name_or_nil` policy: a dynamic base
anywhere ⇒ skip) and the node is one of

1. `IndexOrWriteNode` / `IndexAndWriteNode` / `IndexOperatorWriteNode`, or
2. a `CallNode` with a receiver and `attribute_write?` (`C.x = v`, `C[i] = v`), or
3. a `CallNode` with a receiver whose name is in `ARRAY_MUTATORS ∪ HASH_MUTATORS`.

Scope-insensitive (blocks, method bodies, class bodies, top level), tracking only
the lexical class/module prefix, and a NAMED class/module is entered through its
BODY only (its header path and superclass expression are not walked). Wrapping is
applied at insert time in BOTH the harvest path and the `build_project_legacy`
equivalence oracle, so `merge_equals_legacy_build_project` stays honest.

**Same-file scope, verified by a two-file probe**: `a.rb` writes
`XF = [true]` and reads `XF[0]`; `b.rb` mutates `XF[0] = false`. Run together,
BOTH engines still fire `flow.always-truthy-condition` at `a.rb:6:15` — the fold
survives, cross-file mutation does not widen.

## 3. Residues

1. **The evaluator-side elision of a dead arm's WRITES is not built** (spec row
   f20, deliberate). `x = 1; x = "s" if RUBY_VERSION < "3.4"; x.typo` fires on
   the reference for `1` and is silent here.
2. **A `Psych::VERSION` guard's LIVE arm goes quiet too** (row f29): the port
   kills both arms because it cannot read the constant. Under-emission by
   construction; the alternative was a false positive (§ 1.2). It would close if
   rigor-rs ever grows a Ruby sidecar that can read the analyzer's own constants.
3. **`WIDENED[k] == <literal>` stays quiet where the reference still fires**
   (rows g23/g24). Upstream's `Dynamic[T]` keeps `T`'s pinned value visible to
   the `==` constant fold, so `1 == 1` still folds to `true` there and reports
   always-truthy; the port's `Type::Dynamic(inner)` is opaque to that fold. This
   is a NEW gap — before the change those two rows were BOTH — and it is the
   price of the widening. Closing it means teaching the port's `==` fold to look
   through `Type::Dynamic`, a precision increase with its own FP surface, and it
   is not what the sweep site needs (rake's `if LN_SUPPORTED[0]` is a bare read).
4. **The cvar half of #540 is a no-op in the port.** `@@x` lowers to the nameless
   `Node::VariableRead` / `Node::VariableWrite` and is already `Dynamic[top]`, so
   there is no cvar index to widen. Probed: an unmutated `@@flags = [true]` with
   an `@@flags[0]` read is silent on the REFERENCE too, so the reference's cvar
   widening is not observable at the diagnostic level on that shape either.
5. **The census is a second whole-file Prism walk per lowering.** The reference
   pays the same walk in `ScopeIndexer`. Not measured as a regression; if it ever
   shows up, it can be folded into the main lowering walk.
