# `local_reach` hoist + memo (#422): outcome

#422 reported that `rigor check` over the 16,623 installed-gem files never
finished. It landed as gh-stack #434:
- #432 hoists the syntax-only scans into a per-AST `ReachIndex`;
- #433 memoises `Typer::local_reach`.

The two merged together as `3beeed5` on 2026-10-30. Both were Approved in
review round 1. Output is byte-identical to master everywhere master
finishes.

## Cause

`local_reach` (`crates/rigor-infer/src/reach.rs`) is a backward, depth-first
walk over every write that reaches a read. It had no memo. The only bound is
`seen.len() >= 4`, and it re-enters each write's value up to four times, so
it makes about 4^3 × C(W, 4) calls for W writes of one local. Each call also
ran full syntax-tree scans (`closure_bound_elsewhere`,
`unrecorded_closure`, …), so a single call cost O(W·N).

#385 (`0b05b06`, the #368 fix) made this reachable from every `if` predicate
in every file, through `dead_positions` → `expr_truthiness`. Before #385,
only call-argument checks reached it.

**Lesson: the gates cannot see time.** #385 passed the 0-FP sweep while five
real gem files went from under 1 s to more than 15 minutes. Only timing each
gem file found it (local branch `proto/422-tools`).

## Fix

- **#432, `ReachIndex`.** Every scan that reads only the syntax tree moved
  into an index built once per `LoweredAst`: scope shapes, closures, write
  events per name, case-clause spans, carriers, def exits and `call_self`.
  - It is memoised on the `Typer` by (AST address, arena length).
  - Node sets, arena order, tie-breaks and early returns are master's.
- **#433, `reach_memo`.**
  - **Key:** (AST, root, both ends of `use_span`, `skip_class_guards`,
    `seen.len()`).
  - **Validity:**
    - the `seen` membership answers the entry recorded still hold;
    - the dead set has the same `Rc` identity, which is fresh at scan start,
      at each publish and at scan end;
    - every predicate fold it saw re-entered still answers `None`.
  - **Bounds and checks:** an LRU of 128 variants per key, and an audit
    mode, `RIGOR_REACH_MEMO_AUDIT=1`, that recomputes on every hit.

**The re-entry rule is not the brief's.** The brief said never to store an
entry that saw a re-entry, as the reference's `MEMO_REFUSE_TRANSIENT` does.
Under that rule `loopmix_48` stayed at 27 s. The rule that landed is exact:
- a fold still running and a fold that finished with `None` cannot be told
  apart;
- a fold that lands on a value drops the entry.

The review proved the guard load-bearing with the shape
`q = 1; x = 1; while c; x = 1 if q; q = x; y = 2 if q; end`.

**Only the audit sees two of the rules.** The review broke one rule at a time
in control binaries:

| broken rule | output diffs | audit panics |
|---|---|---|
| re-entry guard removed | 0 of 3,105 programs | 24 |
| `seen` membership ignored | 0 of 600 | 9 |

CI does not run the audit yet (#439).

## Residue and follow-ups

- **#436: the lexer-F0/F1 residue.** `advance` writes `p` 324 and 691 times,
  so the memo's validity is in effect keyed on the whole `seen` stack, and the
  work stays about W^4. The design review found that the reference has no
  backward walk: it runs one forward pass with a 3-pass loop fixpoint, and its
  budget principle is to return the gradual floor. Porting that principle as a
  reaching-write fan-out cap of 256 measured 0.2–0.6 s on both lexers and 31 s
  for the whole gem tree. It changes no file below a fan-out of 176.
- **#435: a pre-existing master FP.** `always-truthy` fires after a loop where
  the reference's last fixpoint pass widens every local the body writes.
- **#437: a coverage loss.** A predicate fold memoises a fuel-starved first
  visit.
- **#438: memory.** The `class_ivar_scope` memo is keyed per read span, which
  costs 7–21 % more RSS on synthetic classes with thousands of defs.
- **#439: the audit is not a CI gate.**
