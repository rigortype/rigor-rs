# LSP `rootUri` — the project root the CLIENT names (2026-08-26)

Closes S4b's deferred **N4**, carried since 2026-07-19 and listed as divergence 3
in both the [stage-3](20260725-lsp-stage3-parity.md) and
[`exclude:`](20260725-lsp-exclude-parity.md) notes: the LSP derived its project
root from the SERVER PROCESS's cwd and never read `initialize`. An editor that
opens folder X but spawns the server elsewhere discovered **zero project files**
and — because an empty project deliberately does not trip the scale guard —
disclosed nothing at all.

Blast radius: `crates/rigor-cli/src/lsp.rs` + `crates/rigor-cli/tests/lsp_check_parity.rs`
+ the `docs/PORT_BACKLOG.md` line. No `rigor-infer` / `rigor-parse` / `rigor-rules`
/ `rigor-index` / `config.rs` edit, and **no change to `check`** (byte-verified
below).

## 1. Probe — where the root is derived, and everything downstream of it

Derivation, single site: `lsp.rs:141` (pre-slice) — `let root = PathBuf::from(".")`,
with `run_stdio` discarding the `initialize` params except for the watched-files
capability bit (`client_supports_watched_files_registration`, `lsp.rs:275`).
`ServerContext::project_root` (`lsp.rs:1050`) carries it for the session; it is
immutable after startup.

Everything that consumes it, and **how**:

| # | consumer | site | root reaches it via |
|---|---|---|---|
| 1 | `.rigor.yml` path | `read_project_config` → `Config::read(root.join(".rigor.yml"))` (`lsp.rs:1648`) | threaded |
| 2 | plugin overlays (`Gemfile.lock`, ADR-72) | `build_core_index` → `cfg.effective_plugins(root)` → `bundler::auto_detected_overlays(root)` | threaded |
| 3a | project `sig/` (`signature_paths:`, ADR-0033) | `cfg.all_signature_dirs(root)` → `Config::signature_dirs` (`config.rs:550`) | **process cwd — the root is NOT threaded into it** |
| 3b | `rbs_collection.lock.yaml` (ADR-0034) | `rbs_collection::discover(_, project_root, _)` (`config.rs:566`) | threaded |
| 4 | project discovery (`paths:`) | `build_overlay` → `project_files` → `discovery_spellings` → `join_root` (`lsp.rs:1006`) | threaded, but see §2 |
| 5 | `exclude:` matching | `ExcludeMatcher{root, paths, patterns}` (`lsp.rs:465`), tiers 2/3 (`push_spellings`, `survives_discovery`) | threaded, but see §2 |
| 6 | watched-file scoping | `touches_configured_root` (`lsp.rs:1911`) canonicalizes `join_root(root, p)` | threaded |
| 7 | config **reload** | `invalidate` → `reload_config(ctx.project_root)` (`lsp.rs:1621`) | threaded |
| 8 | `didChangeWatchedFiles` glob registration | `register_watched_files` (`lsp.rs:2194`) — bare string globs `**/*.rb`, `**/.rigor.yml`, `**/Gemfile.lock`, `**/sig/**/*.rbs` | **root-independent**: a string `globPattern` is matched by the CLIENT against ITS workspace folders |
| — | analysis cache (ADR-0017), baseline (ADR-22) | — | the LSP uses neither |
| — | sidecar | `Sidecar::spawn` runs `ruby -e <embedded script>` | no path input; inherits the cwd |

The sidecar, the `CoreIndex`, the overlay and the rayon pool are all built **after**
the handshake; `Connection::stdio`'s IO threads own only stdin/stdout; `--log` is
accepted-but-unwired, so no path is captured before the root is known. That matters
for §2.

## 2. Why threading an absolute root is the WRONG mechanism

Rows 3a, 4 and 5 are the finding. Passing an absolute root through the existing
`project_root` seam looks like a two-line change and is not:

- **Row 3a would still be wrong.** `Config::signature_dirs` builds bare
  `PathBuf::from(entry)` from `signature_paths:` — cwd-relative by construction and
  shared with `check`. A client root threaded into the LSP would leave the project's
  own `sig/` looked up beside the *spawn* directory. That is one of the three
  breakages the task statement names ("wrong `sig/`"), and the seam does not close it.
- **Rows 4/5 would REGRESS.** `join_root` deliberately produces *relative* strings at
  the default root, because `Config::is_excluded` globs the path string **as `check`
  spells it** — `lib/sub.rb`, or `./lib/sub.rb` under `paths: ["."]`. Hand it an
  absolute root and every relative `exclude:` pattern silently stops matching, so the
  LSP publishes markers `check` suppresses. That re-opens exactly the presence
  divergence [`20260725-lsp-exclude-parity.md`](20260725-lsp-exclude-parity.md)
  closed, in the code that already needed three review-caught regressions (B1-B3) to
  get right. The existing suite would not have caught it: its
  `RootSpelling::Absolute` cells "agree vacuously" (that note's N3) precisely because
  relative patterns match nothing on either side there.

**So: rigor's project root IS a process cwd — in all five places.** The honest
expression of that model is to move the cwd, not to grow a sixth notion of "root"
alongside it.

## 3. The decision

**Root selection.** `initialize`'s three fields, read in the protocol's own
modernity order, first one that yields a filesystem path wins:

| field | status | shape |
| --- | --- | --- |
| `workspaceFolders` | current (3.6+) | `[{uri, name}] \| null` |
| `rootUri` | deprecated in favour of `workspaceFolders` | `DocumentUri \| null` |
| `rootPath` | deprecated in favour of `rootUri` (1.x legacy) | plain path `\| null` |

`null` and `[]` both mean "no folder open" and fall through. `rootPath` is a plain
path, not a URI, and is taken verbatim. The URI decode goes through the **same**
`file_uri_to_path` the buffer decoder now delegates to — a second decoder here is
the drift class the `exclude:` slice exists to prevent (the root's decode and a
buffer's decode disagreeing would let a buffer under the root be spelled outside it).

**Adoption: `std::env::set_current_dir`, once, immediately after the handshake.**
The server ends up in exactly the state `cd <root> && rigor check` runs in, `root`
stays `PathBuf::from(".")`, and every consumer in §1 is byte-identically the code
that ran before. The parity bar then holds **by construction** rather than by
argument — which is the whole point, given that the two mechanisms it protects
(exclude spellings, discovery order) are the ones with a regression history.

A `chdir` is normally a smell; the reasons it is not one here are all checkable:
`rigor lsp` is a dedicated single-session process, it runs once on the main thread,
nothing has touched the filesystem yet (§1's last paragraph), and buffer URIs are
absolute so no request path depends on the cwd. A root that cannot be entered does
**not** abort the server.

**Multiple workspace folders: the FIRST wins, and the rest are disclosed.** rigor's
configuration model is single-root — one `.rigor.yml`, one `paths:`, one `sig/` —
so there is no honest way to serve N folders from one session. The three candidates:

- *pick one silently* — the exact failure this slice removes (markers that do not
  match `rigor check`, with no way for the user to tell why);
- *refuse to start* — makes the server useless in a VS Code multi-root workspace
  that merely happens to contain a Ruby project, which is a common shape;
- *pick the first and say so* — the **ADR-0036 posture-disclosure precedent** this
  server already follows for the sidecar posture and the overlay scale guard: rigor
  never silently degrades. Chosen.

"First" rather than "the folder that has a `.rigor.yml`": a content heuristic would
let *adding a config file to another folder* silently move the root, and the
`check` model ("the root is where you ran it") has no such heuristic either.

**Disclosure policy.** Only degradations get a `window/showMessage`:

| situation | in force | disclosure |
| --- | --- | --- |
| one usable folder / `rootUri` / `rootPath` | that root | **none** — the feature working is not a degradation |
| N > 1 folders | folder 0 | WARNING naming the winner, the losers, and the two remedies |
| named root is not a `file:` directory (`vscode-vfs:`, `untitled:`) | the cwd | WARNING |
| named root cannot be entered (deleted, a file, unreadable) | the cwd | WARNING |
| nothing named | the cwd | none — the documented default, unchanged |

**`workspace/didChangeWorkspaceFolders`: a NON-GOAL, and protocol-honest.** The
server does not advertise `workspace.workspaceFolders.supported` /
`changeNotifications`, so a spec-compliant client will not send it — the non-goal is
enforced by the capability set, not merely documented. Substantively it also buys
little: under the single-root rule, *adding* a folder cannot change the answer
(folder 0 still wins), so only *removing folder 0* matters, and that is rare enough
that a restart is the honest answer. Making the root swappable means re-deriving the
config, the `CoreIndex`, the overlay, the exclude matcher and the cwd mid-session —
an `invalidate` plus a root swap, i.e. its own slice.

**The watcher registration is UNCHANGED, deliberately.** Bare string `globPattern`s
are matched by the client against its own workspace folders, so they are already
root-independent. In a multi-root workspace the client may send events for files in
a folder rigor is not analysing: a `.rb` there is not under any configured root, so
`reharvest_sources` ignores it (`touches_configured_root`); a `.rigor.yml` there
classifies `Structural` and costs one needless rebuild that re-reads *our* config.
Wasteful in a case already disclosed as degraded, never wrong. Scoping the watchers
with a 3.17 `RelativePattern{baseUri}` would need a client-capability probe and is
out of this slice's blast radius.

## 4. What changed

- `requested_root(&Value) -> RootRequest` — **pure** (no filesystem, no connection),
  so the precedence rule is unit-testable on its own. Carries the chosen `path`, the
  raw `named` spelling of the highest-priority field that named anything (for the
  unusable-root disclosure), and `ignored_folders` (for the multi-root one).
- `enter_project_root(&Value) -> Vec<(MessageType, String)>` — the half that touches
  the world: the `chdir` plus the disclosures it owes.
- `run_stdio` calls it between the handshake and `read_project_config`. The ordering
  is load-bearing and commented: everything below reads the filesystem relative to
  the cwd.
- `uri_decoded_path(&Uri)` now delegates to a new `file_uri_to_path(&str)`; one
  decoder, two entry points.
- `multi_root_message` / `unusable_root_message`.

Preserved unchanged: `ServerContext::project_root` is still `.` (its doc now says
*why* that is deliberate rather than incidental), the shared `discovery_spellings`
walk, `ExcludeMatcher`'s three tiers, `reload_config` on structural invalidation,
`swap_project`'s generation bump + `crossfile.clear()`, the held-harvest /
cross-file-cache tier-1 lifecycle, and `check`'s behaviour.

## 5. Tests — 6 new, each re-broken

5 E2E in `lsp_check_parity.rs` (real `rigor lsp` and real `rigor check`, two
processes) + 1 pure unit test. Every E2E test spawns the server in a directory that
is **not** the project, so a regression to the cwd root fails them by producing the
single-file answer.

| test | pins |
| --- | --- |
| `lsp_honours_root_uri_over_the_process_cwd` | **the parity bar**: LSP == `check` for the client's root; carries its own control (no client root ⇒ empty project ⇒ silent) and asserts a single usable root discloses nothing |
| `lsp_honours_workspace_folders_and_the_legacy_root_path` | the other two field forms reach the same answer |
| `lsp_multi_root_takes_the_first_folder_and_discloses` | first folder wins + the disclosure names winner and losers; the second folder's `.rigor.yml` (proved effective by a `check` run there) is NOT in force |
| `lsp_reads_the_rigor_yml_under_the_client_root_not_the_cwd` | the config path moved: a `.rigor.yml` in the CWD is ignored (leg 1), the ROOT's is honoured (leg 2), against a firing control |
| `lsp_ingests_the_project_sig_dir_under_the_client_root` | §2 row 3a — the consumer a threaded root would NOT have fixed. Neither harness nor `fp_audit` can see project-`sig/` behaviour, so it is pinned end to end |
| `lsp::tests::requested_root_follows_the_protocols_modernity_order` | the precedence with all three fields present, `null`/`[]`/empty-string fallthrough, percent-decode, virtual-scheme fallthrough, multi-root ordering |

The **no-`rootUri` cwd fallback** is not a single test: `lsp_findings` — which every
one of the 9 pre-existing parity tests goes through — sends no root at all, so the
fallback is the standing regression bar for the whole file.

**Non-vacuity — five mutations, each reverted:**

| mutation | fails |
| --- | --- |
| `enter_project_root` returns early (pre-slice behaviour) | all 6 new tests; the 9 pre-existing ones still pass |
| multi-root takes the LAST folder | `lsp_multi_root_…` + the unit test |
| `rootUri` consulted before `workspaceFolders` | the unit test (`left: Some("/w/uri")`, `right: Some("/w/folders")`) |
| unusable root falls back silently | `lsp_falls_back_to_the_cwd_and_discloses…` |
| multi-root picks the first folder silently | `lsp_multi_root_…` |

**One expectation was wrong and was corrected, not asserted around.** The first cut
asserted that a buffer in the NON-chosen folder is silent. It is not: an
out-of-`paths:` buffer is analysed against the chosen root's full project index —
the pre-existing divergence 6 / S4b N5, which this slice neither creates nor closes.
The test now records that behaviour explicitly and pins the discriminating property
(the second folder's config is not in force) instead.

## 6. Still divergent between the LSP and `check`

The `exclude:`-note list, with **item 3 (project root = process cwd) CLOSED and
removed**. Items 1 (no baseline), 2 (a panicking buffer publishes nothing rather
than `internal-error`), 4 (no `--bleeding-edge` flag), 6 (out-of-`paths:` buffers
use the full index), 7 (hover/completion are not `exclude:`-gated) and 8 stand
unchanged. Item 5 (`.rigor.yml` read once) was already closed by the
[config-reload slice](20260801-lsp-config-reload.md).

New, recorded rather than silently done: **the root is fixed for the session** —
`didChangeWorkspaceFolders` is a non-goal (§3), and in a multi-root workspace only
folder 0 is analysed.
