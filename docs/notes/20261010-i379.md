# Issue #379 — nested-body sibling writes drop indexed records

PR #387, merged `55fc569` (head `417155b`). Two independent approvals
(Opus `devin acp` gate; Grok 4.6 advisory) + Fable 5.1 design companion.

## What landed

`[1].each { [2].each { h.default ||= 0; h[:a].frobnicate } }` — the inner
body's own earlier statement is a `closure_mutations` record keyed to the
inner call. `flow_children` returns a body-owning node's body statements as
its own `Barrier`-edged children, but `closure_descend` applied earlier
siblings under the *inherited* owner — the re-key to `owner = id` happened
only on descent into the site-holding child, one level too late. The inner
write never matched → `call.undefined-method` FP in-body.

Fix: `Barrier` siblings under a body-owning `id` (`Call{block_span: Some}` /
`Node::Lambda`) apply with `owner = id`; all other shapes keep the inherited
owner. `owns_deferred_body` is now the single predicate shared by the
collection key (`closure_mutations`) and the replay (`closure_descend`) —
companion-review extraction so the two definitions cannot drift.
