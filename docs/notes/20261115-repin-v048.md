## 3. Families

### Ported — the mixin-call recording rework (#2995, #3004, #3007, #2998, #3010)

Upstream `ScopeIndexer` + `MixinAccumulator` now read a `main.include` from
every lexical-self `include` spelling the new `MainSelfCalls` collector
reaches — bare, `self.include`, `send` / `__send__` / `self.send` (never
`public_send`: `main`'s `include` is private) — at the top level, under
control flow, in value positions, in a top-level `def` / `def self.` body, and
inside a self-keeping iterator's block on a literal receiver.

Ported in `rigor-parse`'s `ancestry_facts.rs` (one commit):

- `collect_main_self_calls` mirrors `MainSelfCalls.collect` (CONTROL_FLOW
  kinds, `SELF_KEEPING_ITERATORS` / `RECEIVERLESS_ITERATORS` tables, literal
  receivers = Array/Range/Integer).
- `record_mixin`'s instance-side gate: a lexical-self `include` in
  `main_self` files → `toplevel_includes`; other lexical-self mixin calls
  record constant targets in any spelling (was: `self.`/`send` spellings
  wildcarded). A call naming no constant taints the side; a partially named
  one records + taints.
- `extend` records `self.extend M` / send spellings; `self` argument maps to
  the owner (as upstream).
- `Const.singleton_class.send(:prepend, P)` records like `.prepend P`
  (`singleton_class_include_recorded?`); `send(:include)` stays a taint.
- `class << Const` is walked as the constant's singleton class.

**Measured:** fixture 124's 2 FPs closed; match 953 → 959/1063 (+3, new
reference rows the port now covers). Fixture extended with oracle-measured
rows for every new shape (`self.include`, `__send__`/`self.send`,
`public_send` non-record, `if`/`def`/value-position/`each`+`map` literal
records, non-literal-receiver and lambda non-records).

### NOT ported — the alias-mutation floor (#2677)

Upstream PR `d40140778` adds ~840 lines (`alias_mutation_floor{,/foreign_
locals,/reach,/site_collector}.rb` + hooks in `statement_evaluator`,
`mutation_widening`, `remover_holder_scan`). A local handed to another holder
(copy `g = f`, container slot, ivar, call argument, closure capture) goes
stale when the object mutates through another name; the floor is upstream's
`UnknownStoreWidening.widen_store` / `callee_block_floor` fed `Dynamic[top]`
arguments, applied at flow-evaluation time per shape-mutator call.

**Repro (fixture 168, oracle-measured):**

```ruby
f = [1]; g = f; f[0] << 2; g[0].upcase   # ref silent; port fires `for 1`
```

Same family, same fixture: `{a: 1, b: 2}` copied then `g[:a] = 9` (port keeps
`1`, ref reads `1 | Integer`); `[a, 2]` + `a << nil` → `f[0]`; `a.each {|v|
v << nil}` → `a[0]`; `arr = [a]` + `arr[0] << 9` → `a`.

This is an issue-scale port (alias links + reach + foreign locals + the
gradual `widen_store` semantics, plus sweep validation). The port's
`argument_floor_writes` (#2515 callee floor) is the adjacent machinery but
does not model object-identity links.

## 5. Lessons

- `visit_leaf_node_leave` must decrement the depth tracker the way
  `visit_branch_node_leave` does — the port's `compact_children` missed the
  leaf hook and silently dropped every sibling after the first branch's
  leaves, which looked like "MainSelfCalls never fires" until the visitor was
  instrumented.
- `rigor check` run from the repo root reads the repo's `.rigor.yml`; use
  `harness/probe.py` (fresh cwd per engine) even for one-off probes — a direct
  run from a wrong cwd showed zero diagnostics where probe showed the real
  pair.
