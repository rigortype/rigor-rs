`git bisect run` over the 42 commits (probe: does the reference emit
`call.undefined-method` at `rdoc-7.2.0/lib/rdoc/markup/table.rb:26`?) names the
single cause:

> **`861b08b9` — "Auto-wire the bundled rigor-rbs-inline plugin by default" (ADR-93).**

All four new diagnostics are inside vendored `rdoc-7.2.0` and exist only because
the reference now reads inline `#:` annotations without being asked
(`table.rb` types `other` as `Object` via `#: (Object) -> bool`, so
`other.header` / `.align` / `.body` become undefined-method; plus one
`call.argument-type-mismatch` in `markdown.rb:15874`). They are **reference-only
→ coverage gaps → FP-safe**, and they land squarely on the port's known
**inline-RBS deferral** ([ADR-0035](../adr/0035-inline-rbs-deferred.md)) — i.e.
this bump did not create a new gap *class*, it made an existing one measurable
on a corpus that carries `rbs-inline` annotations.

Two consequences for `UPSTREAM.md` hazard 1: the plugin `-I` pin is no longer
merely defensive (the pin is now post-auto-wire, so the reference *does* require
`rigor-rbs-inline` at startup), and the reference's inline-RBS surface is now on
by default in every oracle run.

## Why the rest is neutral

The 42 commits are dominated by CLI/plugin-resolution (`#194` version-skew
guard, `doctor`), CI cache validation, perf, and handoff docs. The two real
inference additions are both **off in every default profile**:

- `a84efcbd` ADR-67 WD6 — call-site parameter inference on the check walk, behind
  the new opt-in `parameter_inference:` gate (schema-governed, off by default;
  hard-refuses `--incremental`).
- `c051ed71` + `lib/rigor/inference/void_tail_summary.rb` (new, 220 lines) —
  transitive void provenance feeding `static.value-use.void`, which stays
  `--bleeding-edge` (already the port's recorded stance, Phase 3).

Smaller behaviour commits (`48a7af6c` constructor-massign init writes,
`74a46d91` IO/File line iteration non-escaping, `29fbca8f` pre-pass receiver
skip) measured **0 delta** across the ~9200 files above.

`UPSTREAM.md` step 5 (re-measure ported constants): `ARRAY_NEW_TUPLE_LIMIT` is
still `16` in `method_dispatcher.rb` at `v0.3.0` — no re-port needed.
