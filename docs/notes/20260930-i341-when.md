# Issue #341 — `when`-condition / `in`-guard writes stay out of scope reach

PR #351, merged `c25a86c` (rebased head `5410433`). One adversarial round, Approved.

## What landed

`local_reach`'s span scan picked up writes inside `when` CONDITIONS and `in`
patterns/guards — the reference never scope-evaluates those
(`Narrowing.case_when_scopes` is shape-analysis only). `reach.rs` gains
`unevaluated_case_clause_spans`, collecting every `Node::When`'s `conditions`
span plus `body[0]` of each `in`-clause `BeginRescue` carrier (identified by the
sibling `UnmodeledWrite` marker at the same span; Prism folds `in P if/unless G`
into the pattern `IfNode`, so guards ride the same extent). Excluded from:

- `local_reach`'s `in_region`/`guards_here`
- `ivar_reach` for class-body/top-level writes (def-body kept — the reference's
  class-ivar table is a text scan)
- `latest_definite_assignment`/`definitely_assigns` (the second leak path for
  `in Integer if (q = 1; true)`)

Review found the fix also killed a broader master FP family: bare post-case
reads, `x = case…end`, `foo(case…end)`, `while`-body interior reads — all went
from FP to silent, matching the reference.

## Measured

~45-probe review + 8-corpus sweep: 0 FP; every issue-row shape silent; all
must-still-fire controls (body writes, `else`, subject writes, `in`-body writes,
rescue/while/ternary/begin) fire identically; ivar boundary correct both ways;
#334 composition verified.

## Residuals

- **#355** — `Float(<unresolved call>)` fires `for Float` on unresolved
  receivers (pre-existing, unrelated to `case`).
- **#356** — `while`/`until` bodies should bind clause-extent writes via
  `loop_body_local_writes` (safe-side coverage loss introduced by this diff;
  `for`/`each`/`loop do` unaffected).
- **#357** — modifier `rescue` carrier still leaks the condition write (same FP
  family through a different reach path).
