# Effects slice 5 — the snapshot and command surface: a probe

2026-08-28. Investigation only, no production code kept. Everything measured
against the PINNED submodule at `v0.3.4` (`b10bd5df`), populated into this
worktree from the parent checkout at the pin (never the network, never
`REFERENCE_RIGOR_DIR`), invoked as
`ruby -I reference/rigor/lib -I reference/rigor/plugins/rigor-rbs-inline/lib …`
from the project directory each measurement names, with `.rigor/cache` cleared
either side of every oracle run. Real projects were COPIED into a temp project
first; the user's checkouts were only ever read.

Subject: [ADR-0043](../adr/0043-effect-system-port-parity-model.md) slice 5 —
"`rigor effects` + `--format=json` + `effects update` / `check` / `diff`", gated
on "snapshot byte-comparable modulo the excluded header". `--format=json` and
the report already shipped in slice 2, so what is actually left is the snapshot
family — and the arc's standing conclusion is that the **transitive lane was
DECLINED** ([slice-4 probe](20260826-effects-s4-probe.md)). The question this
probe exists to answer is whether the parity artifact survives that.

**Headline: it does — the transitive lane is NOT what blocks the artifact. The
taint bit is. And the omission rule inverts ADR-0043's soundness direction,
which the standing gate cannot see.**

- **`methods:` is the DIRECT lane, and `reach:` is EMPTY BY DEFAULT.**
  `Snapshot.build_methods` reads `entry.direct` (`snapshot.rb:218`) — the
  collector's own-body summary, which is exactly what the port computes today.
  `build_reach` returns `{}` when `effects.snapshot.reach:` is empty
  (`snapshot.rb:228`), and that key defaults to `[]`
  (`configuration.rb:718`). **A project that configures nothing gets a snapshot
  whose transitive half is the literal two characters `{}`.** Measured, not
  inferred (§ 1b, § 1c).
- **The port's DIRECT label lane is already at 99.3 % against that table.**
  Graded against the oracle's snapshot `methods:` rather than against the
  report's transitive lane, mastodon/app is **MATCH 5985 / UNDER 963 / OVER 0**
  with only **49 missing labels** across 6,948 methods — versus 1,489 missing
  when the same binary is graded against the transitive report (§ 2).
- **What blocks byte-parity is `unresolved:`, and it is the slice-4 wall wearing
  a different hat.** Of mastodon's 1,301 shared default rows, **1,005 differ in
  nothing but `unresolved:`** and 158 more in `exhaustive:`; only **128 are
  byte-identical**. 4,503 of the oracle's 4,525 parameterised
  `dynamic-receiver(…)` causes carry a TYPER-INTERNAL reason code
  (`unsupported_syntax` ×3297, `inferred_return_untyped` ×1206) that a
  typer-free port cannot produce (§ 3).
- **THE TRAP: over-taint is UNDER in the report and OVER in the artifact.**
  `omit?` drops a row that is exhaustive-and-trivial. The port marks
  `TypeFree#owned_writer` non-exhaustive where the oracle does not — both sides
  agree on `effects: ["mutate.local"]` and on the origin bundle — so the oracle
  OMITS the row and the port would WRITE it. That is "a method rigor-rs reports
  that the reference does not", which ADR-0043 § 2 calls an OVER-CLAIM that
  fails the gate. `harness/effects_diff.py` scores both rows `UNDER` and the
  whole corpus `0 OVER` (§ 5a).
- **Two destructive surfaces the port has never had.** `rigor effects update`
  overwrites its target with **no guard of any kind** — measured on a
  hand-written file, silently replaced, exit 0 (§ 5b). And a project caught by
  the #114 declared-lane self-defense reports `methods: {}`, so a naive
  `update` would write an EMPTY snapshot over a committed one — **data loss on
  correct, annotated code**, which is precisely the population that adopts
  effects (§ 5c).
- **The ADR's command list is stale**: the pin ships **four** verbs, not three.
  `explain` is missing from ADR-0043 § 5's row 5, and so are `--strict-tolerated`
  and `--baseline` (§ 4).
- **Recommendation: BUILD A SUBSET, and build the instrument first.** The
  highest-value piece is not a command at all: teach `effects_diff.py` to grade
  the SNAPSHOT shape (it needs no port code — it can synthesise the port's
  snapshot from the JSON the port already emits, which is how the omit-inversion
  above was found). Then ship `update` + `check` + `diff` restricted to the
  `methods:` table with a hard refusal to write when the report is suppressed.
  `explain` and `reach:` stay out (§ 8).

## 1. The artifact, exactly

### 1a. The schema

`Effects::Snapshot#to_yaml` (`snapshot.rb:338-347`) is a **hand-rolled
JSON-compatible YAML subset** — deliberately not `YAML.dump`, so the leading
comment, the key order and the flow sequences are upstream's own. Measured
output (`harness/effects-corpus/01_core_origins`, default config):

```yaml
# .rigor-effects.yml — generated by `rigor effects update`. Commit it; review its diff.
schema: 1
rigor: "0.3.4"
vocabulary: 1
config_digest: "44136fa355b3678a1146ad16f7e8649e94fb4fc21fe77e8310c060f61caaff8a"
methods:
  "Origins#cvar_write":
    effects: ["mutate.static"]
  …
reach: {}
```

| element | rule | source |
|---|---|---|
| line 1 | fixed comment, `HEADER` | `snapshot.rb:43` |
| `schema:` | integer `1`, bumped when the shape changes | `:41` |
| `rigor:` | `Rigor::VERSION`, JSON-quoted | `:342` |
| `vocabulary:` | `registry.vocabulary_version`, bare integer | `:343` |
| `config_digest:` | `SHA256(JSON.generate(canonicalize(configuration.effects \|\| {})))` | `identity.rb:90-101` |
| key order | `schema`, `rigor`, `vocabulary`, `config_digest`, `methods`, `reach` — fixed, never sorted | `:340-345` |
| row order | `table.sort_by { key }` — byte-stable, pooled run == sequential run | `:375-377` |
| label order | the `LabelSet`'s own sorted `to_a` | `:263-269` |
| scalars | `value.to_s.to_json` for every key and every label; integers bare | `:365-373` |
| sequences | flow style, `", "`-joined | `:366` |
| empty table | the literal `methods: {}` / `reach: {}` | `:353-356` |
| omitted fields | `declared:` when empty, `exhaustive:` when true, `unresolved:` when empty | `:60-66` |
| trailing | exactly one `\n` | `:346` |

**Determinism holds.** Two consecutive `update --full` runs over one tree are
byte-identical (measured). ADR-0020's determinism rule therefore transfers to
this file without a new argument, and the sort keys are the file's own.

Of the four header fields, **only `rigor:` necessarily differs.** `schema:` and
`vocabulary:` are constants the port must track deliberately, and
`config_digest:` is a pure function of the parsed `effects:` block —
reproducible. `SNAPSHOT_HEADER_KEYS` excluding all four is therefore *more*
normalisation than the divergence requires, and excluding `schema:` in
particular hides the one field whose whole job is to say "an older reader would
misread this file". See § 6.

### 1b. `methods:` is DIRECT — measured, on a project where the two differ

`build_methods` (`:213-221`) passes `entry.direct.proven`, `entry.direct`,
`declared: entry.direct.declared`; `entry_for`'s defaults then take
`direct.exhaustive?` and `direct.causes` (`:262`). `build_reach` (`:227-239`)
passes `entry.proven` / `entry.exhaustive?` / `entry.causes` — the transitive
readings (`effect_table.rb:17-20`).

On `harness/effects-corpus/02_propagation`, with
`effects.snapshot.reach: ['**/*.rb']` so both tables are populated:

| symbol | `methods:` (direct) | `reach:` (transitive) |
|---|---|---|
| `Pipeline#run` | `effects: []` | `effects: ["io.fs.read", "io.output.stdout"]`, `exhaustive: false` |
| `Recursive#mutual_a` | `effects: []` | `effects: ["nondet.time"]` |
| `Pipeline#load_input` | `effects: ["io.fs.read"]` (exhaustive) | same labels, `exhaustive: false` |

This is the measurement the probe turned on. The declined transitive lane
governs **`reach:` only**. `methods:` needs no call graph, no fixpoint, no edge
resolution, and no answer to "which calls did the reference's typer visit".

### 1c. `reach:` is opt-in, and empty by default

`Configuration#coerce_effects_reach` defaults `effects.snapshot.reach:` to `[]`
(`configuration.rb:718`, `:756-766`); `build_reach` returns `{}` for an empty
glob list (`snapshot.rb:228`). `update` even says so on stderr:

```
rigor: wrote .rigor-effects.yml (12 method(s), 0 reach entries)
rigor: note — `effects.snapshot.reach:` is empty, so the snapshot records `methods:` only.
```

An entry is either a **file glob** (anything carrying `* ? [ ] / .`) matched with
`File.fnmatch?(…, File::FNM_PATHNAME)` against the project-relative defining
file, or a **preset name** registered by a plugin's `effect_entry_points:`
manifest field (`entry_points.rb:23-31`; five plugins declare one —
actioncable, actionpack, activejob, actionmailer, railties). An entry point is
therefore a **FILE**, not a method: every unit written in a matching file
qualifies (`:226`, `entry_point?` at `:241-246`). The same `omit?` rule then
applies to the table.

So the honest statement of the artifact's shape is: **a `reach:`-less snapshot
is not a different file wearing the name — it is the file the reference itself
writes for every project that has not opted in.** What a `reach:`-less port
snapshot *would* be is a file that silently disagrees with a project that HAS
opted in, which is a configuration the port must refuse rather than approximate
(§ 8).

### 1d. The omission rule

```ruby
def omit?(trivial:, direct:, proven:, declared:)
  return true if trivial                       # exhaustive ∧ proven ⊆ {mutate.local} ∧ rendered_declared ∅
  return true if proven.empty? && declared.empty?
  return false unless direct.exhaustive?
  return false if direct.bundles.empty?
  direct.bundles.each_key.all? { |o| SYNTHESISED_ORIGINS.include?(o.to_s) }   # {construct:attr-writer}
end
```
(`snapshot.rb:293-300`; `trivial?` is `summary.rb:82-83`.) Every input is
available to the port from its own `--format=json` (`effects`, `declared`,
`exhaustive`, `direct`). It is also the mechanism of § 5a's trap.

`--full` keeps everything. On mastodon/app the two settings are **6,948 rows vs
1,340** — the default table is 19 % of the full one.

## 2. The producible fraction, measured

`harness/effects_diff.py` grades the port's `effects` key against the oracle's
REPORT, which is the TRANSITIVE lane. Against the oracle's SNAPSHOT `methods:`
table — the DIRECT lane, the thing slice 5 is actually gated on — the same
binary scores very differently:

| corpus | graded against the report (transitive) | graded against the snapshot `methods:` (direct) |
|---|---|---|
| fixtures (10) | MATCH 348 UNDER 270 | **MATCH 351 UNDER 267** |
| mastodon/app | MATCH 5217 UNDER 1731 (missing-label **1489**) | **MATCH 5985 UNDER 963 (missing-label 49)** |
| both | OVER 0, DECLARED-MISMATCH 0 | OVER 0, DECLARED-MISMATCH 0 |

**6,899 of mastodon's 6,948 methods carry exactly the direct proven label set
the oracle records.** The label lane is not the gap.

The remaining UNDER is 914 methods where the port is more tainted than the
oracle's direct bit. An env-gated probe (`RIGOR_PROBE_DIRECT_BIT`, reverted)
resolved the port's edge taints against an EMPTY selector set — i.e. computed
the DIRECT bit rather than slice 3's transitive stand-in — and moved the number
by **three** (914 → 911, MATCH 5985 → 5988). So the over-taint is **not** the
edge-selector stand-in; it is the port's own direct causes firing where the
reference's typer answered. Swapping the bit is not the fix.

### Why `unresolved:` is unreachable

`render_causes` (`:276-279`) renders each direct taint cause as
`cause` or `cause(detail)`. Over mastodon's `--full` snapshot, 891 distinct

| rendering | count | port-reachable? |
|---|---|---|
| `dynamic-receiver(unsupported_syntax)` | 3297 | **no** — a reference-typer reason code |
| `dynamic-receiver(inferred_return_untyped)` | 1206 | **no** — same |

[fixture-corpus blind spot](20260731-survey-fp-triage-24.md) again, and the
reason PR #112 put a real project in the standing set.

## 4. The command inventory — what the PIN ships

ADR-0043 § 5 row 5 names `update` / `check` / `diff`. The pin ships **four**
verbs (`effects_snapshot_command.rb:35`, `VERBS = %w[update check diff explain]`)
plus flags the ADR does not mention. Everything below is measured, not read.

| verb | writes | reads | exit codes |
|---|---|---|---|
| `update` | `effects.snapshot.path` (default `.rigor-effects.yml`) | config + sources | 0 always; 64 on usage; **uncaught `Errno::ENOENT`** when the path's directory is absent |
| `check` | nothing | the snapshot + config + sources | **0** fresh, **0** tolerated-only drift, **1** gating drift, **64** usage, **64** unparseable snapshot |
| `diff` | nothing | same | **0 always** — never gates |
| `explain` | nothing | the live effect table (+ the diff, without `--symbol`) | **0 always** |

Flags, from `--help` on each verb:

| flag | `update` | `check` | `diff` | `explain` |
|---|---|---|---|---|
| `--config=PATH` | ✓ | ✓ | ✓ | ✓ |
| `--format=text\|json` | ✓ | ✓ | ✓ | ✓ |
| `--full` | ✓ (changes the FILE) | ✓ (changes the recomputed side) | ✓ | ✓ |
| `--strict-tolerated` | accepted, inert | ✓ | ✓ | ✓ |
| `--no-tolerated-effects` | accepted, inert | ✓ | ✓ | ✓ |
| `--baseline=PATH` | — | ✓ | ✓ | ✓ |
| `--symbol=KEY` | — | — | — | ✓ |

**`--no-tolerated-effects`**, precisely: it replaces the discharge policy with
`Discharge.none` and the tolerated list with `[]` at JUDGMENT time
(`effects_snapshot_command.rb:94-97`). It is **inert on `update` and on the
report** — the record is undischarged by design (`snapshot.rb:31-33`), and
`update --no-tolerated-effects` was measured **byte-identical** to `update`.
Under `check` it is the switch that turns a tolerated-only pass into a failure:

```
effects.tolerated: [io.output]        →  check           exit 0 (prints a `tolerated:` section)
                                         check --strict-tolerated   exit 1
                                         check --no-tolerated-effects exit 1 (event moves to `methods:`)
```

**Verbs without the transitive lane.** All four are meaningful, because
`methods:` is the whole of the default artifact:

- `update` — meaningful. Writes the direct table, which is the file.
- `check` — meaningful, and the reason the artifact exists (the CI gate).
- `diff` — meaningful; same comparison, never gating.
- `explain` — **not** meaningful. Its `reach:` half is `PathFinder.shortest`
  over the propagated edge set (`effects_snapshot_command.rb:162-170`), i.e.
  exactly the declined lane; its `methods:` half is a one-line origin lookup the
  port's `direct:` key already exposes. Measured: `explain --symbol Pipeline#run`
  prints `Pipeline#run → Pipeline#load_input → File.read [io.fs.read]` — a path
  the port cannot compute. `explain` is slice 4's, not slice 5's.

Other measured surface facts:

- **The verbs take no paths**: `effects update lib/foo.rb` → exit **64**,
  `"rigor effects update takes no paths; it records the configured paths:"`.
- An **unknown verb falls through to the report**: `rigor effects bogus` exits
  **0** with no output (`bogus` becomes a positional path that resolves to
  nothing). The port's `unknown option` handling must not diverge here — it is
  what `effects_diff.py`'s `NOT-IMPLEMENTED` detection keys off.
- A **corrupt snapshot is 64, not 1**: `rigor: effect snapshot load failed: …:
  methods: expected a mapping, got Array`.
- A **missing snapshot is drift, not an error**: `check` exits 1 with
  `no snapshot; run \`rigor effects update\``; `diff` exits 0 with the same body.
- A **header mismatch** produces `regeneration:` events that fail **both** gates
  (`snapshot_diff.rb:50-51`, `:161-169`), and every symbol then re-reads as
  added.
- **`gate: additions` does not excuse a rename**: measured exit 1, because the
  addition half of the rename gates (`ADDITIVE_CATEGORIES`).
- An **unregistered `reach:` preset raises** — `reach: [rails]` with no plugin is
  an uncaught `EntryPoints::Error` with a Ruby backtrace, exit 1.

`diff --format=json` is a stable contract worth writing down, because it is the
half a port must match exactly:

```json
{"fresh": false,
 "events": [{"category": "symbol-added", "symbol": "Origins#brand_new_effect",
             "table": "methods", "tolerated": false, "detail": "[io.fs.read]"}],
 "footer": {"added_symbols": 1, "removed_symbols": 0},
 "header": {"snapshot": ".rigor-effects.yml", "gate": "symmetric",
            "recorded": {…4 header fields…}, "current": {…}}}
```

Eleven category strings, fixed (`snapshot_diff.rb:35-45`).

## 5. The traps

### 5a. THE trap — `omit?` inverts ADR-0043's soundness direction

ADR-0043 § 2: "rigor-rs may be **more** tainted than the reference and stay
sound", and "a method rigor-rs reports that the reference does not is an
OVER-CLAIM and fails the gate". Both are true of the REPORT. Through the
snapshot's omission rule they **contradict each other**, because `omit?` reads
the taint bit:

```
oracle  TypeFree#owned_writer  effects ["mutate.local"]  exhaustive TRUE   → trivial? → OMITTED
port    TypeFree#owned_writer  effects ["mutate.local"]  exhaustive FALSE  → not trivial
                                                                          → not (proven ∅ ∧ declared ∅)
                                                                          → `return false unless direct.exhaustive?`
                                                                          → KEPT
```

Both engines agree on the label set *and* on the origin bundle
(`construct:receiver-mutation`); the only difference is the bit, and the bit is
the safe direction by § 2. The result is a symbol in the port's record that the
oracle's record does not carry — an OVER-CLAIM by § 2's other rule.

Measured: `harness/effects-corpus/07_mutators`, **2 rows**
(`TypeFree#owned_writer`, `TypeFreeSingleton.owned_writer`).
`harness/effects_diff.py` grades both `UNDER: extra-taint` and reports
`OVER=0` for the corpus. **The standing gate is structurally blind to this
class**, and it is the same shape as every other lesson in this arc: a
suppression/relaxation that is safe on one surface is unsafe on the next one
down.

Consequence for any slice-5 spec: the port's snapshot writer may **not** apply
`omit?` to its own bit. The sound rule is *omit whenever either reading would
omit* — i.e. suppress a row the oracle would call trivial, which for a
label-agreeing row means treating `proven ⊆ {mutate.local} ∧ declared ∅` as
omission regardless of the port's taint bit. That is strictly an under-claim and
it is the only direction that survives.

### 5b. `update` is the port's first destructive command, and upstream guards it with nothing

Measured: a file containing `HAND WRITTEN, DO NOT DESTROY` at
`.rigor-effects.yml` was silently replaced by `rigor effects update`, exit 0.

`write` (`effects_snapshot_command.rb:77-85`) is `File.write` and a stderr line.
No `--force`, no backup, no "this file was not generated by rigor" check, no
`--dry-run`, no confirmation. The doc comment states the position outright:
"there is no generate / regenerate split, because a snapshot has no 'already
exists' hazard: it records observations, so overwriting it is the whole point".

That reasoning holds **only while the writer is the reference**. It does not
transfer to a port whose record is a measured subset of the reference's: a
rigor-rs `update` over a snapshot generated by the reference silently downgrades
a committed artifact, and the next `rigor effects check` (reference) then reads
39 removed symbols on mastodon as real drift. The port inherits the command but
not the argument for its safety.

Two further sharp edges on the same command:

- **`update --full` then a plain `check` DRIFTS.** Measured on 02_propagation:
  exit 1, `symbols: +0 / -6`. `--full` is a property of the WRITE and `check`
  recomputes without it, so a project whose dev habit is `update --full` and
  whose CI runs `check` fails forever. Any port `check` must recompute with the
  same `--full` as the file it is judging — and the file does not record which
  it was.
- **`effects.snapshot.path:` into a non-existent directory is an uncaught
  `Errno::ENOENT`** with a Ruby backtrace. A port must decide whether to mirror
  the crash or route it; either way it is a divergence to record.

### 5c. The #114 self-defense turns `update` into data loss

The shipped declared-lane self-defense (`crates/rigor-cli/src/effects/mod.rs:196`)
reports `methods: {}` for any project that could produce a declared lane —
`effects.attribution:`, `effects.envelopes:`, a `plugins:` list, or a `%a{…}`
anywhere in `sig/` or the sources. Measured port output on
`04_declared`, `09_declared_envelopes`, `10_declared_plugins`: **0 methods**.

An `update` implemented as "render the report" would therefore write

```yaml
methods: {}
reach: {}
```

over a committed snapshot, on **correct, annotated code** — and annotated code
is exactly the population that commits a snapshot in the first place. Upstream
has a superficially similar hazard (`Propagator.propagate` rescues
`StandardError` → `EffectTable.empty`, `propagator.rb:60-61`) but it fires only
on an internal error; the port's fires on the normal case.

The self-defense that makes the REPORT sound makes the ARTIFACT destructive.
A port `update` must **refuse to write** — non-zero, with a message naming the
suppression — whenever `carries_effect_annotations` is true. It is not enough to
write an empty file "safely": an empty snapshot is not an under-claim once it
lands on disk, it is a deletion.

### 5d. Exit codes vs this repo's CLI conventions

`check`'s codes (0 fresh / 1 drift / 64 usage) match `rigor check`'s
findings-versus-usage split, so nothing new is needed. Two edges do need a
decision:

- **A tolerated-only drift exits 0 while printing drift** and leaving the file
  stale. `fresh?` and `drift?` are different predicates (`snapshot_diff.rb:113-125`)
  and the exit code follows `drift?`. A port that conflated them would be a
  silent CI regression in the permissive direction.
- **An unparseable snapshot is 64**, the usage code — not 1 and not a crash. The
  port's own `--format` errors already use 64, so this is consistent, but it has
  to be deliberate: the natural reading of "the file on disk is broken" is a
  data error, not a usage error.

### 5e. `explain` reads the live table, not the record

`explain --symbol Pipeline#run` printed a `reach:` path on a project whose
snapshot has `reach: {}`. `rows_for_symbol` consults `@table`
(`effects_snapshot_command.rb:133-141`), not the file. So `explain` is not
gated by the `reach:` configuration at all — another reason it belongs to the
transitive slice rather than this one.

## 6. The text renderer, and its parity bar

The default (non-JSON) surfaces are three:

- **`update`** — two stderr lines, no stdout.
- **`check` / `diff`** — `EffectsDiffRenderer`: `No effect drift against PATH.`
  when fresh, otherwise `Effect drift against PATH:`, sections in the fixed
  order `snapshot`, `header`, `methods`, `reach`, `tolerated`, a
  `symbols: +N / -M (a rename is one of each)` footer, and the closing line
  `Run \`rigor effects update\` and commit the result if this change is intended.`
  Markers are `+ label`, `- label`, `≤+ label`, `≤- label`,
  `materialised label (declared → proven)`, `+symbol [detail]`, `-symbol [detail]`,
  and `-? label (current summary is not exhaustive)` for a hedged removal
  (`effects_diff_renderer.rb:25-37`).
- **`explain`** — `reach:` / `methods:` sections, `sym → sym → sym [label]` or
  `sym [label] ← origin`.

**The bar is not stated anywhere, and that is the finding.** ADR-0002's "message
wording is allowed to diverge (and improve)" is scoped, in its own first line, to
`rigor check`'s diagnostic set; ADR-0043 § 1 re-scopes ADR-0002 to `rigor check`
explicitly. ADR-0043 § 3 says only that the **snapshot** is byte-comparable
modulo the header, and says nothing about `check`/`diff` prose. Grepping
ADR-0043 and AGENTS.md for a wording clause returns exactly one hit, and it is
about `rigor check` being byte-identical when effects are off.

The gap should be closed by decision, not by default, and the honest split is:

| surface | bar | why |
|---|---|---|
| `.rigor-effects.yml` | **byte-identical** modulo `rigor:` | it is committed, diffed in review, and read by the other implementation |
| `diff --format=json` | **exact** on categories, keys, footer, header fields | it is a machine contract |
| `check` / `diff` / `explain` text | **wording may diverge**, ADR-0002's latitude | it is prose for a human |
| exit codes | **exact** | CI depends on them |

If instead byte-parity on the prose were required, slice 5 would be a
substantially larger and much less valuable slice: it would pin `≤+`, the
`…?` suffix, the `(a rename is one of each)` parenthetical and the closing
sentence, none of which any consumer reads.

## 7. The price

The arc's recent decisions were each settled by one measured number
(#104 = 1.2 % of wall; slice 4 = 0 OVER impossible; slice 6 = +2 MATCH across
36,167 methods). Slice 5's:

**What a snapshot would cover.** mastodon/app: **1,340 method rows** by default
(6,948 under `--full`), of which the port produces 1,301 with **0 only-port
keys**. Zero `reach:` rows unless the project opts in; with an
`app/controllers/**/*.rb` glob, 781 default / 1,771 full — none of them
producible.

**What the port would get right.** 1,301/1,340 rows present (97 %),
**1,133/1,301 rows correct if `unresolved:` is set aside** (87 %), **128/1,301
byte-identical** (9.8 %) as things stand, against a structural ceiling of
**254/1,340** (19 %).

**What the diff catches that `--format=json` does not.** Exactly four things,
and the first is the one that matters:

1. **omission-rule divergence** — the § 5a inversion. Invisible to
   `effects_diff.py` by construction; found in one run by a snapshot-shaped
   grader.
2. **cause rendering** — `render_causes`' `cause(detail)` spelling and its
   `uniq.sort`. 1,005 mastodon rows differ here and the report-level grader does
   not compare causes at all (`lanes()` reads only `effects`, `declared`,
   `exhaustive`).
3. **serialisation and ordering** — the ADR-0020 surface for anything we write.
4. **the header** — `schema:` and `vocabulary:` are real pin-tracking facts that
   `SNAPSHOT_HEADER_KEYS` currently discards.

**Is `SNAPSHOT_HEADER_KEYS` worth wiring up? Yes — and it is worth more than the
commands.** The decisive point is that it needs **no port code at all**: the
grader can synthesise the port's snapshot from the JSON the port already emits
(`effects`, `declared`, `exhaustive`, `causes`, `direct` are every input `omit?`
and `entry_for` take), render it with upstream's rules, and compare. That is how
§ 5a was found, in a throwaway script, before a single line of `update` existed.
Wiring it costs ~120 lines in `effects_diff.py` and immediately converts a
whole class of artifact-level over-claims from invisible to fatal. It should
also **narrow** the exclusion set from four keys to one (`rigor`), because
`schema:`, `vocabulary:` and `config_digest:` are all reproducible and all
carry information.

**What shipping the commands buys, by contrast**: a `rigor effects check` that
agrees with the reference on 128 of 1,340 rows today. As a CI gate against
*itself* that is fine — drift between two rigor-rs observations is 100 %
precise, which is the whole `db/schema.rb` argument. As a **parity** artifact it
is not close, and the gap is not closable without the typer.

## 8. Recommendation — BUILD A SUBSET, instrument first

Three of the arc's last four decisions were "don't, and here is what to do
instead". This one is not quite that, because § 1b changed the premise: the
artifact **is** producible, `reach:` is the only structurally blocked part, and
`reach:` is empty by default. But the ADR's gate as written — "snapshot
byte-comparable modulo the excluded header" — **cannot be met**, and would be a
fourth vacuous gate if adopted unchanged.

In order:

1. **Wire the snapshot comparison into `harness/effects_diff.py`** (no port
   code). Synthesise the port's snapshot from its JSON, render with upstream's
   `omit?` + serialiser, compare body-only against a real oracle `update`.
   Verdicts: `SNAPSHOT-OVER` (a row the oracle's record does not carry) is
   **fatal** and is a new gate the current one cannot express; row-field
   mismatches are UNDER. Narrow `SNAPSHOT_HEADER_KEYS` to `{"rigor"}` and
   compare the other three. **This slice pays for itself the moment it lands:
   it fails today, on `07_mutators`, on two rows.**
2. **Fix the omit-inversion first** (§ 5a): a row whose labels are within
   `{mutate.local}` and whose declared lane is empty is omitted regardless of
   the port's taint bit. Strictly an under-claim; gated by step 1.
3. **Then ship `update` / `check` / `diff`, `methods:`-only**, with three hard
   refusals, each of which is a *decline*, not an approximation:
   - **refuse to write when the report is suppressed** (§ 5c) — non-zero, naming
     the producer that triggered it. An empty snapshot is a deletion.
   - **refuse when `effects.snapshot.reach:` is non-empty** — the port cannot
     produce that table and a `reach: {}` beside a configured glob is a false
     record, not an under-claim.
   - **refuse to overwrite a file whose `rigor:` header is not the port's own**
     (§ 5b) — a reference-written snapshot downgraded by the port is the one
     data-loss path the reference's "overwriting is the whole point" argument
     does not cover.
4. **Do not ship `explain`** (§ 4): its `reach:` half is the declined lane and
   its `methods:` half is a lookup the JSON already exposes. Keep the current
   `not yet implemented` message for it, pointing at slice 4 rather than 5.
5. **Restate the gate in ADR-0043.** "Byte-comparable modulo the excluded
   header" is unmeetable while `unresolved:` carries typer reason codes (§ 3).
   The meetable gate is: *the port's `methods:` key set is a subset of the
   oracle's; every row's `effects:` and `declared:` are byte-equal; the port's
   `exhaustive:` may only be `false` where the oracle's is `true`; `unresolved:`
   is UNGRADED and the port writes its own causes.* On mastodon that gate is met
   by 1,133 of 1,301 rows today and fails on the 10 `effects:` rows and the 39
   absent ones — which are honest, attributable debt rather than a number that
   cannot move.

And one correction to record regardless of what is built: **ADR-0043 § 5's row 5
lists three verbs where the pin ships four**, and § 3's claim that the artifact
"holds `methods:` as direct summaries **and** `reach:` as the transitive
footprint" is true of the code and misleading about the default — the reference
writes `reach: {}` for every project that has not opted in.
